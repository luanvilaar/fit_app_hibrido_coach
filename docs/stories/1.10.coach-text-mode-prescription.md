# Story 1.10 — Modo texto para prescrição na velocidade do Excel

Status: InReview

## Objetivo

Permitir que o coach escreva a sessão inteira em taquigrafia de teclado, com a estrutura montada ao vivo ao lado, alcançando a velocidade de digitação da planilha sem abrir mão do editor estruturado.

## Fonte de requisitos

- Story 1.9 — calendário, editor de sessão e colagem TSV do coach.
- Observação de campo: treinadores prescrevem no Excel porque a planilha é linear e sem mouse.

## Contexto

O editor da Story 1.9 é campo a campo: cada série exige focar dois `TextInput`, cada exercício um card. O modal "Colar do Excel" ataca o problema pela metade — é importação one-shot, não superfície de escrita — e tem três defeitos estruturais:

1. Não cobre blocos de texto livre (Condicionamento/LPO/Endurance), justamente o conteúdo mais digitado.
2. Round-trip quebrado: `serializeSessionToTsv` emitia `# BLOCO`/`# TEXTO` que o parser descartava.
3. Delimitador decidido pela primeira linha do documento.

## Critérios de aceitação

- [x] O coach alterna entre Formulário e Texto sem perder o que já montou.
- [x] A DSL cobre todo o `BlockForm`: força, skill, condicionamento com ranking, séries de LPO e volumes de endurance.
- [x] O parse é tolerante — nunca lança e sempre devolve uma árvore utilizável, com diagnósticos por linha.
- [x] Digitar não cria ids nem remonta o formulário; os ids sobrevivem a renomear, inserir, remover e reordenar.
- [x] Linhas coladas do Excel (TSV) são reconhecidas no mesmo campo do texto.
- [x] Ida e volta entre os modos preserva o que a DSL não expressa (`restSeconds`, categoria do movimento).
- [x] Testes cobrem gramática, round-trip, reconciliação e a UI.

- [x] Implementar a gramática: inferência de categoria pelo nome, modificadores `::`, prescrição com séries heterogêneas.

- [x] Cobrir gramática, round-trip, reconciliação, componente e integração com os gates do projeto.

## Decisões de design

- **A DSL descreve `blocks`, não a sessão.** Título, data, equipe, visibilidade e recado continuam no formulário. Isso torna a unidade da DSL igual a `LibraryTemplateForm.blocks`, e o mesmo modo texto serve o calendário e a biblioteca sem código extra.
- **O `::` só é emitido quando a inferência pelo nome discordaria da categoria real.** `# Força principal` volta limpo; `# Aquecimento` com categoria Condicionamento volta como `# Aquecimento :: cond`. Round-trip garantido sem poluir a escrita.
- **O parser não valida números.** `reps` e `load` são string no modelo e `buildCoachSessionPayload` já valida no envio. Os diagnósticos do parser são consultivos, sobre estrutura, evitando duas validações que poderiam divergir.
- **Ids são criados só no commit.** Os ids (`block-1`, `item-2`) são exclusivamente chaves de render do React — `buildBlocksPayload` não os emite. Digitar não avança o contador global nem remonta componentes.
- **A DSL só sobrescreve o que a categoria do bloco expressa.** Um bloco convertido em Condicionamento guarda os exercícios; um de Força guarda a descrição. É a regra que torna a ida e volta não destrutiva e que preserva `restSeconds`.
- **CSV não é autodetectado.** A vírgula é sintática na DSL (`3x5 @70%, 2x3 @80%`) e detectá-la destruiria séries heterogêneas. O Ctrl+C do Excel produz TSV, então na prática nada se perde.

## Fora de escopo

Campos de sessão na DSL; realce de sintaxe dentro do campo; autocomplete de exercícios no modo texto; modo texto otimizado para mobile; DSL de semana inteira; sintaxe para `restSeconds`; tempo/RPE (o modelo não tem onde guardar).

## Dev Agent Record

### Debug Log References

- Diagnóstico de exercício qualitativo precisou migrar para o fechamento do bloco: as observações chegam em linhas `|` posteriores ao exercício, então a checagem no empilhamento acusava falso positivo.
- Casamento de bloco por `nome|categoria` perdia a identidade quando só a categoria mudava; resolvido com um passe intermediário por nome apenas.
- O guard `Platform.OS !== "web"` no atalho de teclado tornava o código inalcançável nos testes (o ambiente roda como `ios`) sem alterar o comportamento — removido, já que no nativo os modificadores chegam indefinidos.

### Completion Notes List

- O modo texto cobre as cinco categorias de bloco e devolve `BlockForm[]` com os ids preservados.
- O dialeto TSV é decidido por linha, o que corrige de saída o bug de delimitador da Story 1.9.
- O round-trip virou teste de aceitação: 12 fixtures verificam `parse(serialize(b)) === b` a menos de ids, e a idempotência de `serialize(parse(serialize(b)))`.
- `PrescriptionPasteModal` continua funcionando e não foi removido — a aposentadoria é decisão de produto pendente, já que o TSV agora cola direto no modo texto.
- `slugify` passou a ser exportado de `coach-calendar.ts` para reuso pela gramática.
- `fontFamilies.mono` adicionado aos design tokens; alinhar colunas de DSL sem monoespaçada é inviável.
- Validações: lint, typecheck, 43 suítes / 431 testes e build web com 18 rotas.
