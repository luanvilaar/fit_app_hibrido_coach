# Story 1.39 — Recuperação do acompanhamento no schema cache

Status: Ready for Review

## Story

**As a** coach FitBlock,
**I want** abrir o acompanhamento de atletas e equipes mesmo após uma divergência de migration,
**so that** a tela não fique inutilizável por uma RPC ausente ou um cache de schema desatualizado.

## Critérios de aceitação

1. As três RPCs de acompanhamento existem no banco, mantêm a cadeia de autorização coach/owner → equipe → atleta e só permitem leitura.
2. Um reparo forward idempotente restaura as RPCs e recarrega o schema do PostgREST sem reintroduzir execução de atleta para owner.
3. O repositório preserva o código seguro retornado pelo Supabase.
4. A UI identifica `PGRST202` como divergência de schema e apresenta orientação acionável, mantendo a opção de tentar novamente.
5. Testes cobrem contratos das RPCs, o código `PGRST202`, retry da tela e não introduzem RPCs de escrita.
6. Lint, typecheck, testes, build e `git diff --check` passam antes da conclusão.
